Своя прошивка CM-530 на C

Вместо RoboPlus Task можно написать прошивку контроллера самому. Тогда скорость, тайм-ауты и логику задаёшь ты, и нет лимита в 50 переменных. Камера у нас стала читаться почти без ошибок, хотя через Task давала -1 почти на каждом чтении.

Чем придётся заплатить. Своя прошивка заменяет заводскую, поэтому R+Task-проги на ней не работают, а движения из R+Motion надо проигрывать самому (см. ниже). Обратно на заводскую можно вернуться за пару минут, так что пробовать не страшно.

Зачем это нужно

  • Скорость. Главный цикл крутится так быстро, как напишешь, без скрытых пауз интерпретатора.
  • Своя связь с устройствами. Сам решаешь, сколько ждать ответа камеры и что делать при сбое, а не получаешь молчаливое -1.
  • Нормальный язык. Массивы, функции с параметрами, сколько угодно переменных, свой проигрыватель движений.
  • Минусы: всё, что раньше делала заводская прошивка (движения, пульт, кнопки), придётся писать или переносить самому.

Что внутри CM-530

  • Процессор STM32F103RE: Cortex-M3, 72 МГц, 512 КБ флеш, 64 КБ ОЗУ.
  • Шина Dynamixel (серво и камера) — USART1, связь с ПК по USB — USART3.
  • Python сюда не поставить: MicroPython не поддерживает семейство F1. Если нужен Python рядом с роботом, это отдельная плата (ESP32, Pico) или камера v3.

Карта флеша

адресчто
0x08000000загрузчик, 12 КБ, защищён от записи
0x08003000прошивка (заводская или твоя), 128 КБ
0x08023000программа Task, 128 КБ
0x08043000движения .mtnx, 244 КБ

Окирпичить нельзя: загрузчик защищён. Вернуть заводскую прошивку: RoboPlus Manager → восстановление прошивки (порт выбери вручную, при поиске выключи и включи плату). После этого программу и движения залей заново.

Шаг 1. Что скачать

  1. Embedded C SDK для CM-530 с сайта ROBOTIS (бесплатно). Внутри 11 готовых примеров: светодиоды, кнопки, связь с ПК, зуммер, микрофон, моторы OLLO, ИК-датчик, чтение и запись Dynamixel, групповая запись (SYNC WRITE), пульт RC-100.
  2. WinARM 2008 (gcc 4.3.0), его ROBOTIS даёт к SDK. Это архив: распаковал и пользуешься, ставить не надо, на Windows 11 работает.

Собирай только WinARM. Современный arm-none-eabi-gcc собирает тот же код без единой ошибки, прошивка заливается, контрольная сумма сходится, и ничего не работает. Мы на этом потеряли вечер. Сборка без ошибок тут ничего не значит. Eclipse не нужен, хватает make из WinARM.

Шаг 2. Устройство проекта

Самое простое — скопировать папку примера и править её. В каждом примере одно и то же:

proj\camera\
  APP\src\main.c        ← твой код
  APP\inc\dynamixel.h   ← функции шины Dynamixel
  stm32f10x_lib\        ← библиотека процессора от ST
  stm32.ld              ← карта памяти (старт с 0x08003000, уже настроено)
  Makefile
  → после сборки: CM530.bin  (его и заливаешь)

Для сборки хватает маленького bat-файла: добавить WinARM в PATH и вызвать make в папке проекта.

set PATH=C:\путь\toolchain-winarm\bin;C:\путь\toolchain-winarm\utils\bin;%PATH%
cd proj\camera
make

Шаг 3. Первая прошивка: связь с ПК

Возьми пример 03 SERIAL COMMUNICATION: он отвечает Welcome! на букву w. Если после сборки и заливки плата ответила, значит всё настроено правильно, и можно писать своё.

В SDK есть печать только в шестнадцатеричном виде (TxDWord16). Для отладки сразу допиши печать обычного числа:

void TxDDec(u16 v) {
    char buf[6]; int i = 0;
    if (v == 0) { TxDByte_PC('0'); return; }
    while (v > 0) { buf[i++] = '0' + v % 10; v /= 10; }
    while (i > 0) TxDByte_PC(buf[--i]);
}

Шаг 4. Как заливать

  1. Войти в загрузчик. Открой COM-порт (57600) и непрерывно шли в него символ #, затем один раз нажми RESET на плате. Ответ: SYSTEM O.K. (CM530 Boot loader …). Выключением питания в загрузчик не попасть: когда плата выключена, USB-порт пропадает из системы.
  2. Отправь Enter, потом l + Enter. Загрузчик сотрёт память и ответит Ready...
  3. Отправь файл одним потоком, без пауз: пауза считается концом передачи.
  4. В конце отправь ещё один байт: сумму всех байтов файла по модулю 256. Без него запись не проходит (именно поэтому RoboPlus Terminal показывает размер на единицу больше файла).
  5. Загрузчик ответит Size: … Checksum: XXXX-XXXX, половины должны совпасть. Команда go запускает прошивку.

Всё это легко автоматизировать. Скелет на Python (нужен pip install pyserial):

import serial, time
data = open("CM530.bin", "rb").read()
s = serial.Serial("COM3", 57600, timeout=0.05)

print("Нажми RESET на плате...")
buf = b""
while b"SYSTEM O.K." not in buf:      # сыплем # и ловим загрузчик
    s.write(b"#"); time.sleep(0.04)
    buf += s.read(200)
time.sleep(0.5); s.read(1000)

s.write(b"\r"); time.sleep(0.2)
s.write(b"l\r")                       # стереть и ждать файл
while b"Ready" not in s.read(200): pass

s.write(data + bytes([sum(data) % 256]))   # файл + байт суммы, без пауз
time.sleep(1); print(s.read(500).decode(errors="ignore"))
s.write(b"go\r")                      # запустить

Лайфхак: вставь в прошивку команду, которая по символу с ПК сама перезагружает плату (NVIC_GenerateSystemReset()). Скрипт заливки сначала шлёт этот символ, и RESET жать больше не нужно. Вставляй её в каждую свою прошивку.

Шаг 5. Шина Dynamixel: серво и камера

Функции из dynamixel.h в SDK:

функциячто делает
dxl_initialize(0, 1)поднять шину (1 = 1 Мбит/с, как у AX-12)
dxl_ping(id)проверить, отвечает ли устройство
dxl_read_byte / dxl_read_word(id, адрес)прочитать 1 или 2 байта
dxl_write_byte / dxl_write_word(id, адрес, значение)записать
dxl_get_result()удалось ли последнее чтение. Проверяй всегда

Так наша прошивка читает камеру (кусок настоящего кода):

dxl_initialize(0, 1);
while (1) {
    cx   = dxl_read_word(51, 18);  st1 = dxl_get_result();
    cy   = dxl_read_word(51, 20);  st2 = dxl_get_result();
    area = dxl_read_word(51, 22);  st3 = dxl_get_result();
    if (st1 == COMM_RXSUCCESS && st2 == COMM_RXSUCCESS && st3 == COMM_RXSUCCESS) {
        TxDDec(cx); TxDString("  "); TxDDec(cy); TxDString("\r\n");
    } else {
        TxDString("net otveta\r\n");    // честно видим сбой, а не -1
    }
}

Результат: 24 замера подряд без единой ошибки, при движении мяча около 4% сбоев. Через Task на той же камере сбой был почти на каждом чтении.

Все 18 серво одним пакетом (SYNC WRITE)

dxl_set_txpacket_id(BROADCAST_ID);
dxl_set_txpacket_instruction(INST_SYNC_WRITE);
dxl_set_txpacket_parameter(0, 30);          // адрес цели (Goal Position)
dxl_set_txpacket_parameter(1, 2);           // по 2 байта на серво
for (i = 0; i < 18; i++) {
    dxl_set_txpacket_parameter(2 + 3*i,     i + 1);               // ID
    dxl_set_txpacket_parameter(2 + 3*i + 1, dxl_get_lowbyte(pos[i]));
    dxl_set_txpacket_parameter(2 + 3*i + 2, dxl_get_highbyte(pos[i]));
}
dxl_set_txpacket_length(3*18 + 4);
dxl_tx_packet();      // НЕ dxl_txrx_packet: ответа на SYNC WRITE не бывает

Шаг 6. Движения из .mtnx

Проигрывать свои движения можно, и это работает на роботе. Схема:

  1. Скрипт на ПК читает .mtnx (это XML, см. Motion) и пишет таблицы на C: время каждого шага и 18 углов.
  2. Углы переводятся в деления AX-12: pos = 512 + градусы × 1023 / 300.
  3. Прошивка каждые ~8 мс считает промежуточную позу между двумя шагами (линейная интерполяция) и отправляет её одним SYNC WRITE.
// между позой A и позой B за N тактов по 8 мс
for (t = 1; t <= N; t++) {
    for (j = 0; j < 18; j++)
        pos[j] = A[j] + (B[j] - A[j]) * t / N;
    sync_write(pos);
    wait_ms(8);
}

Перед первым движением включи момент всем серво (dxl_write_byte(BROADCAST_ID, 24, 1)) и плавно, медленно выведи робота в первую позу. Иначе он дёрнется в неё со всей силы.

Как устроить главный цикл

Те же правила, что в Task, только теперь их соблюдаешь ты сам:

  • Никаких долгих ожиданий в главном цикле. Засекай время и проверяй его на каждом проходе.
  • Камеру и серво опрашивай с разумной частотой, а не на каждом проходе: шина общая, и движения начнут дёргаться.
  • Движение — это «состояние»: цикл каждые 8 мс двигает его на шаг дальше, а между шагами успевает прочитать камеру и гиро. Так робот видит мяч прямо на ходу.
while (1) {
    if (now() - t_motion >= 8)   { t_motion = now();  motion_step(); }   // движение
    if (now() - t_camera >= 40)  { t_camera = now();  read_camera(); }   // камера
    if (now() - t_gyro   >= 20)  { t_gyro   = now();  read_gyro();   }   // гиро
    decide();                                                            // логика
}

Грабли, на которые мы наступили

  • Сборка современным GCC: всё выглядит нормально, но ничего не работает (см. шаг 1).
  • SYNC WRITE с ожиданием ответа (dxl_txrx_packet): каждый такт упирается в тайм-аут, движения идут рывками и в 5 раз дольше.
  • Чтение с ПК через библиотечную функцию у нас не заработало. Рабочий вариант — прямо по регистрам: ждать флаг RXNE (USART3->SR & 0x20), а при переполнении (& 0x08) прочитать DR, иначе приём залипает.
  • Если снял момент с серво (регистр 24 = 0), запись новой позиции его не возвращает: робот остаётся мягким.
  • Прежде чем опрашивать все 18 серво, опроси одно. Не ответило — остальные не трогай, иначе 18 тайм-аутов подряд.
  • Приветствие прошивка печатает один раз при старте. Подключился к порту позже — плата кажется мёртвой, хотя всё работает.
  • RoboPlus Terminal не показывает то, что ты набираешь, только ответ платы. Это нормально.
  • Когда выпускаешь новую версию, сохраняй рабочий .bin с понятным именем и датой. Перед соревнованиями это сильно выручает: рабочую версию можно вернуть за минуту.

Custom CM-530 firmware in C

Instead of RoboPlus Task you can write the controller firmware yourself. Then you control speed, timeouts and logic, and there's no 50-variable limit. Our camera now reads almost error-free, while through Task it returned -1 on almost every read.

The price. Your firmware replaces the stock one, so R+Task programs won't run on it, and you have to play R+Motion motions yourself (see below). Going back to stock takes a couple of minutes, so it's safe to try.

Why bother

  • Speed. The main loop runs as fast as you write it, with no hidden interpreter pauses.
  • Your own device communication. You decide how long to wait for the camera and what to do on a failure, instead of getting a silent -1.
  • A real language. Arrays, functions with parameters, as many variables as you like, your own motion player.
  • Downside: everything the stock firmware did (motions, remote, buttons) you have to write or port yourself.

What's inside the CM-530

  • STM32F103RE: Cortex-M3, 72 MHz, 512 KB flash, 64 KB RAM.
  • Dynamixel bus (servos and camera) = USART1, USB link to PC = USART3.
  • No Python: MicroPython doesn't support the F1 family. Want Python near the robot? Use a separate board (ESP32, Pico) or the v3 camera.

Flash map

addresswhat
0x08000000bootloader, 12 KB, write-protected
0x08003000firmware (stock or yours), 128 KB
0x08023000Task program, 128 KB
0x08043000.mtnx motions, 244 KB

You can't brick it: the bootloader is protected. To restore stock firmware: RoboPlus Manager → firmware recovery (pick the port manually, power-cycle the board while it searches). Then re-upload your program and motions.

Step 1. What to download

  1. Embedded C SDK for CM-530 from ROBOTIS (free). It has 11 ready examples: LEDs, buttons, PC serial, buzzer, mic, OLLO motors, IR sensor, Dynamixel read/write, sync write, RC-100 remote.
  2. WinARM 2008 (gcc 4.3.0), provided by ROBOTIS with the SDK. It's an archive: unpack and use, no install, works on Windows 11.

Build only with WinARM. A modern arm-none-eabi-gcc builds the same code with zero errors, it flashes, the checksum matches, and nothing runs. That cost us an evening. A clean build means nothing here. No Eclipse needed, WinARM's make is enough.

Step 2. Project layout

Easiest: copy an example folder and edit it. Every example looks the same:

proj\camera\
  APP\src\main.c        ← your code
  APP\inc\dynamixel.h   ← Dynamixel bus functions
  stm32f10x_lib\        ← ST processor library
  stm32.ld              ← memory map (starts at 0x08003000, already set)
  Makefile
  → after build: CM530.bin  (this is what you upload)

A tiny bat file is enough to build: add WinARM to PATH and run make in the project folder.

set PATH=C:\path\toolchain-winarm\bin;C:\path\toolchain-winarm\utils\bin;%PATH%
cd proj\camera
make

Step 3. First firmware: talk to the PC

Take example 03 SERIAL COMMUNICATION: it answers Welcome! to the letter w. Built, uploaded, got the reply? The whole chain "code → build → upload → run" works, and you can start writing your own.

The SDK only prints hex (TxDWord16). Add normal decimal printing for debugging right away:

void TxDDec(u16 v) {
    char buf[6]; int i = 0;
    if (v == 0) { TxDByte_PC('0'); return; }
    while (v > 0) { buf[i++] = '0' + v % 10; v /= 10; }
    while (i > 0) TxDByte_PC(buf[--i]);
}

Step 4. Uploading

  1. Enter the bootloader. Open the COM port (57600), keep sending #, and press RESET once. Reply: SYSTEM O.K. (CM530 Boot loader …). Power-cycling won't work: the USB port disappears when power is off.
  2. Send Enter, then l + Enter. It erases and replies Ready...
  3. Send the file in one stream, no pauses: a pause counts as end of transfer.
  4. At the end send one extra byte: the sum of all file bytes mod 256. Without it the write fails (that's why RoboPlus Terminal shows a size one byte larger than the file).
  5. Reply: Size: … Checksum: XXXX-XXXX; both halves must match. go starts the firmware.

Easy to automate. A Python skeleton (needs pip install pyserial):

import serial, time
data = open("CM530.bin", "rb").read()
s = serial.Serial("COM3", 57600, timeout=0.05)

print("Press RESET on the board...")
buf = b""
while b"SYSTEM O.K." not in buf:      # spam # and catch the bootloader
    s.write(b"#"); time.sleep(0.04)
    buf += s.read(200)
time.sleep(0.5); s.read(1000)

s.write(b"\r"); time.sleep(0.2)
s.write(b"l\r")                       # erase and wait for the file
while b"Ready" not in s.read(200): pass

s.write(data + bytes([sum(data) % 256]))   # file + checksum byte, no pauses
time.sleep(1); print(s.read(500).decode(errors="ignore"))
s.write(b"go\r")                      # run

Tip: add a command that resets the board on a character from the PC (NVIC_GenerateSystemReset()). The upload script sends it first, and you never press RESET again. Put it in every firmware you make.

Step 5. The Dynamixel bus: servos and camera

Functions from the SDK's dynamixel.h:

functionwhat it does
dxl_initialize(0, 1)start the bus (1 = 1 Mbps, like AX-12)
dxl_ping(id)check whether a device answers
dxl_read_byte / dxl_read_word(id, addr)read 1 or 2 bytes
dxl_write_byte / dxl_write_word(id, addr, value)write
dxl_get_result()whether the last read worked. Always check it

This is how our firmware reads the camera (real code, trimmed):

dxl_initialize(0, 1);
while (1) {
    cx   = dxl_read_word(51, 18);  st1 = dxl_get_result();
    cy   = dxl_read_word(51, 20);  st2 = dxl_get_result();
    area = dxl_read_word(51, 22);  st3 = dxl_get_result();
    if (st1 == COMM_RXSUCCESS && st2 == COMM_RXSUCCESS && st3 == COMM_RXSUCCESS) {
        TxDDec(cx); TxDString("  "); TxDDec(cy); TxDString("\r\n");
    } else {
        TxDString("no answer\r\n");    // see the failure honestly, not -1
    }
}

Result: 24 reads in a row with zero errors, about 4% failures with a moving ball. Through Task, the same camera failed on almost every read.

All 18 servos in one packet (SYNC WRITE)

dxl_set_txpacket_id(BROADCAST_ID);
dxl_set_txpacket_instruction(INST_SYNC_WRITE);
dxl_set_txpacket_parameter(0, 30);          // Goal Position address
dxl_set_txpacket_parameter(1, 2);           // 2 bytes per servo
for (i = 0; i < 18; i++) {
    dxl_set_txpacket_parameter(2 + 3*i,     i + 1);               // ID
    dxl_set_txpacket_parameter(2 + 3*i + 1, dxl_get_lowbyte(pos[i]));
    dxl_set_txpacket_parameter(2 + 3*i + 2, dxl_get_highbyte(pos[i]));
}
dxl_set_txpacket_length(3*18 + 4);
dxl_tx_packet();      // NOT dxl_txrx_packet: SYNC WRITE never replies

Step 6. Motions from .mtnx

You can play your own motions, and it works on the robot. The plan:

  1. A PC script reads the .mtnx (it's XML, see Motion) and writes C tables: each step's time and 18 angles.
  2. Angles become AX-12 units: pos = 512 + degrees × 1023 / 300.
  3. Every ~8 ms the firmware computes the in-between pose of two steps (linear interpolation) and sends it in one SYNC WRITE.
// from pose A to pose B in N ticks of 8 ms
for (t = 1; t <= N; t++) {
    for (j = 0; j < 18; j++)
        pos[j] = A[j] + (B[j] - A[j]) * t / N;
    sync_write(pos);
    wait_ms(8);
}

Before the first motion, enable torque on all servos (dxl_write_byte(BROADCAST_ID, 24, 1)) and move the robot slowly into the first pose. Otherwise it snaps into it at full force.

Structuring the main loop

Same rules as in Task, except now you enforce them:

  • No long waits in the main loop. Record a time and check it each pass.
  • Poll the camera and servos at a sensible rate, not every pass: the bus is shared and motions will start to stutter.
  • A motion is a "state": every 8 ms the loop advances it one tick, and in between it has time to read the camera and gyro. That's how the robot sees the ball while walking.
while (1) {
    if (now() - t_motion >= 8)   { t_motion = now();  motion_step(); }   // motion
    if (now() - t_camera >= 40)  { t_camera = now();  read_camera(); }   // camera
    if (now() - t_gyro   >= 20)  { t_gyro   = now();  read_gyro();   }   // gyro
    decide();                                                            // logic
}

Traps we hit

  • Building with modern GCC: everything looks fine, nothing runs (see step 1).
  • SYNC WRITE waiting for a reply (dxl_txrx_packet): every tick hits a timeout, motions stutter and take 5× longer.
  • Reading from the PC via the library function didn't work for us. Working way: poll registers directly, wait for RXNE (USART3->SR & 0x20), and on overrun (& 0x08) read DR, or reception locks up.
  • After disabling torque (register 24 = 0), writing a goal position does not re-enable it: the robot stays limp.
  • Before polling all 18 servos, ping one. No reply? Skip the rest, or you get 18 timeouts in a row.
  • The firmware prints its greeting once at boot. Connect later and the board looks dead, though it's fine.
  • RoboPlus Terminal doesn't echo what you type, only the board's replies. That's normal.
  • Save every working .bin with a clear name and date. Rolling back to a known-good build before a competition is priceless.
